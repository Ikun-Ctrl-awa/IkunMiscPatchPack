## 0.3.0 测试版更新（2026-10-24）

- **新版适配**：东尼算法与火堆融合分别增加当前工坊原件的独立差分；旧版差分继续保留，按原件SHA-256精确选择，未知版本仍安全跳过。东尼算法仅筛选原版无色牌，不更改全局牌池；火堆融合沿用更多附魔的完整继承流程。

- **配置紧凑布局**：40项的标题、启用开关和展开按钮放在同一行；隐藏重复标题行并保留原生菜单。点击“▶ 展开”显示说明，点击“▼ 收起”折叠。主开关和运行状态持续可见；剧情按键、mod形态自身候选、往昔之章四项概率均随说明折叠，各项独立，设置值不变。子页不再重复显示版本简介，展开状态不写入设置文件。

- **血魔宗**：初始 4 费无色罕见能力牌，首次升级降至 3 费并获得保留，后续升级费用保持 3。兼容 Free Loadout 控制台的突破等级上限、实际等级、克隆、读档与升级预览；作为融合子卡时，按血魔宗自身次数首次降费并给融合牌提供保留，外层或血魔宗子卡开启突破均可继续升级，直接改子卡等级同步外层费用与保留。只有自己的卡牌本体直接伤害敌人才吸血；势不可当、群蛇形态、血肉戏法等能力，开信刀、锁镰等遗物，中毒、灼伤、帝王之征等效果的追加伤害不计入，转传触发卡牌参数也不改变归属。保留卡牌本体的多段、群体、增伤后的实际生命伤害，原生宠物代卡攻击按打出玩家归属判断。不能从自己的卡牌或遗物中直接获得格挡；所有强化等级均允许药水、覆甲、金属化、多层护甲等状态提供格挡。每次打出累计吸血比例：基础与 +1 各增加 100%，+2 及以上各增加 `100+20×(n−1)%`，能力图标下沿用致死性的原生数字角标，显示总比例数值，不加百分号。本场战斗只要打出过任意升级版，就开启溢出回复转临时血池，不受后续普通牌或出牌顺序影响。与攻击牌融合时按素材顺序生效：血魔宗在前的后续攻击可立即吸血；在后的血魔宗不追溯前面已结算的伤害。多张子卡逐张累计倍率，升级子卡实际执行后才开启临时血池。为保留该顺序，含血魔宗的融合牌在合并效果模式下也逐张结算，其他融合牌和全局设置不变。临时血量先于角色生命承伤，战后清除，不增加最大生命；每段按总比例计算实际生命伤害并取整，不计格挡和过量击杀。
- **临时血量兼容**：一次伤害完全由临时血量承受、角色生命未减少时，卷轴的纸伤难愈不扣最大生命，化石追踪者的吮吸不加力量，盛碗虫（石）的失衡仍触发眩晕；临时血量不足时按实际生命损失触发。多段攻击逐段判断，支持先用格挡再用临时血量。
- **石中剑精英任务结算**：修复融合牌未转发胜利回调、战斗副本进度未回写永久牌及完成时移除对象错误。按永久牌上的任务子卡累计 3 次精英胜利，发放原有玉之剑，完成后移除永久牌；同场重复回调去重，普通战斗和 Boss 不计数，保留旧存档已有进度。独立开关，不依赖融合任务移除修复的开关。
- **更多的假遗物：尘封魔典升级牌**：修复“尘封魔典？？？”显示升级牌、实际却给未升级牌的问题。在作者原有选牌和拾取流程中，加入牌组前执行一次原生升级，悬停卡牌预览同步显示升级效果。独立开关默认开启，缺少目标模组时跳过。仅影响今后的拾取，不追溯修改旧存档已领取的卡牌。本机核对目标为“更多的假遗物”1.2.8。

“mod形态”改用青紫魔法卡牌插画。原图嵌入 DLL，卡面、百科小图、详情大图、普通图及测试图读取同一资源；升级、克隆、读档和关闭获取开关后仍保留卡图。无需另外复制图片或 PCK。卡牌效果与状态图标保持原规则。

- **闹鬼的铁砧升级移除**：永久牌组中的铁砧本体或融合子卡自身累计升级到 3 次，立即移除对应永久卡；融合时移除整张融合牌。门槛固定为 3，不读取多次升级附魔改变后的上限，不以融合牌总等级或多个铁砧的等级之和判定。原生批量升级循环及融合重算完成后当场结算，去重调用原生删牌流程；升级预览与战斗临时副本不影响永久牌组。独立开关 `ghostly_anvil_remove`，需要 YUISpireExpansion，缺少模组时安全跳过。

- **融合打击数值显示**：修复融合扩展包的卡面旧变量与实际动态伤害变量不一致。伤害总值和每张素材加成读取原生变量对象，跟随融合素材数、升级和目标状态刷新，保留原始伤害公式与计数规则；支持卡面、百科、升级预览、克隆和读档，不改写翻译原文。独立开关 `fusion_strike_display`。

## 0.2.0 新增内容

- **补丁：YUI 点火附魔结算与保留**。修复永久牌组上的“点火”被战后清理删除的问题，下一场仍可首次触发。战斗内临时附魔仍按原规则清理。点火需由原作者的 **YUI The Spire Expansion - Cards** 提供并注册“魂焰”；单独安装 YUICore 和 Spire 扩展时没有这张生成牌，安装卡牌扩展可恢复原有生成与抽牌加能量效果。同时适配新版卡牌预览接口，恢复附魔说明中的魂焰预览。补丁包不提供替代卡。

- **杂项：剧情可以跳过**。卡牌或效果正在结算时按一次快捷键（默认空格）跳过当前动作剩余的动画等待，完成后自动恢复。每次伤害、充能球生成和钩子仍逐次执行；不修改保存的速度设置和全局时间倍率。支持在该选项下捕获新按键或组合键，重启后生效。选牌、暂停、菜单及文本输入期间不接管按键。

- **杂项：mod形态**。3 费无色稀有能力牌；打出时立即生成一张牌，此后每次你的回合开始时再生成一张。先等概率选择模组，再等概率选择该模组的合格卡牌；仅允许攻击、技能、能力，排除不可生成、不可打出、任务／诅咒／状态卡池内容。生成牌本回合免费，获得虚无与消耗。普通升级生成升级一次的牌；兼容叠影、灼热等允许多次／无限升级的附魔，包括额外附魔槽与复合附魔。形态升级 n 次后，标题与描述显示实际等级，生成牌执行原卡的升级逻辑 n 次。根据附魔实际提供的升级资格适配，有限次数附魔保留上限。多张形态分别保存等级。形态自身默认不参与生成候选；没有其他合格模组卡时，它不会进入正常无色牌获取池，也不会被随机生成。可在“杂项 → mod形态”中打开“mod形态自身参与生成候选”，允许生成另一张形态；此时即使只有这张模组卡，它也会进入无色卡池。该子开关默认关闭，重启后生效。
- **补丁：火堆融合的强化等级与升级资格**。融合等级显示为全部素材的强化等级之和，包括多次强化和再次融合。每次按融合顺序强化首个仍可强化的素材；普通素材强化一次后跳过，自身支持多次强化或带有可多次强化附魔时保留对应能力。全部素材均不可强化时，融合牌也不可强化；诅咒、状态等本身不可强化的素材不会获得无效强化。兼容灼热附魔、预览、克隆和读档，旧存档按实际素材等级校正外层等级，不补做素材强化。血魔宗子卡支持融合牌或子卡自身的控制台突破资格；直接设等级重放升级前还原其4费基线，首升后保持3费和保留；切换突破不重置已有素材，读档保留实际子卡分配。
- **补丁：千咒卷轴 × 更好的进阶：Boss 诅咒**。修复进阶 20 直接把诅咒加入牌组，绕过 YuWanCard 千咒卷轴的问题。进房流程会等待卷轴按原有效果处理本次新增诅咒；仅影响卷轴持有者，保留旧诅咒、原随机结果与遗物的战斗收益上限。需要两个模组均已加载，可独立关闭；不追溯移除修复前已经留下的诅咒。
- **补丁：海克斯复视 × 遗物三选一**。三选一领取选中的遗物时，沿用复视原有复制流程额外获得副本，保留蜡制状态、原有特殊遗物排除和同步规则。同时补齐三选一原有扩展存档的收集入口，保留固定候选及领取状态。关闭选择界面、跳过、重复回调或已领取奖励读档不额外发放。需要海克斯大乱斗与遗物奖励三选一，可独立关闭。
- **补丁：七咒之戒 × 海克斯：Boss 最大生命惩罚**。戒指原来按面板最大生命计算 25% 扣除量，血量锻造器等又把该数值当成基础生命乘上倍率，导致实际扣除远超 25%，甚至在击败 Boss 后触发死亡。补丁只将戒指这次计算改用基础生命，再由海克斯换算一次；保留戒指其余效果、原生扣血与复活钩子。基础生命与扣除量沿用整数取整，结果与直接对面板乘 75% 可能相差少量取整值。需要 YuWanCard 和海克斯大乱斗，可独立关闭；不自动补回旧存档已经损失的生命或复活次数。
- **补丁：多次升级卡牌的升级预览**。修复列表缓存旧等级、自由配装突破等级在预览克隆中丢失、详情页仅考虑一次升级的问题。多次升级牌默认显示当前等级，勾选升级预览后显示下一级，例如 +3 → +4；标题与效果数值同步，不升级原牌，不写回自由配装配置。普通只能升级一次的卡牌保留原版预览方式。此补丁有独立开关。
- **补丁：状态图标附加计数显示**。修复 RitsuLib 状态额外数字标签继承过大自动字号上限、向图标下方撑出巨大数字的问题。附加字号跟随原生状态层数的实际字号；昔涟“飞向粉色的明天”的剩余攻击次数置于左上角，保留右下角层数，避免重叠。不修改次数、伤害、原生普通状态标签或遗物／意图角标。
- **补丁：多重附魔图标优化**。展开更多附魔的附加槽位及 Plague 等复合附魔，在卡面左侧分别显示每个实际附魔的图标、层数和启用状态。支持先后顺序变化、克隆和读档后的显示；显示补丁不额外施加附魔，也不重复执行附魔效果。
- **补丁：Act 4 Heart 优化**。顶栏左上角使用一代原版钥匙凹槽和三色钥匙图；绿在上、红在左下、蓝在右下，未获得时保留深色凹槽，获得后点亮，遗物栏隐藏钥匙。原模组的钥匙身份、存档、奖励和开门检查保留，可与更好的顶栏同时使用。
- **补丁：往昔之章修改**。新局保留原版章节，在对应章节内随机混入一代普通战斗、精英、事件和 Boss，四类默认均 **30%**。RitsuLib 的该补丁下提供四个 0～100% 滑块，重启后生效。普通房间在选择下一房间内容时确定；Boss 在生成地图前确定并使用原生房间存档，避免地图图标与实际 Boss 不符。Act 4 不参与替换。已经生成的旧地图 Boss 保持原样。

各项可独立关闭；关闭形态选项会停止其获取和生成效果，但保留既有卡牌的读取能力。

## 配置

进入 RitsuLib 模组配置，选择“艾堃的杂项与补丁包”。

- **杂项**：更好的顶栏、剧情可以跳过、mod形态、血魔宗，共 4 个选项。

## 剧情可以跳过的按键冲突与范围

原版默认空格在鼠标键盘模式用于 **查看战场（Peek）**，纯键盘模式用于 **选择（Select）**。跳过只在战斗动作正在执行且没有选牌／菜单时接管该按键，其余时候保留原版行为。可以改成其他按键或组合键；本功能不会替你修改原版键位。

跳过沿用原版即时模式与 Cmd 动画等待接口，并提前结束当前动作已经开始的 Cmd 计时器；不提前完成伤害、选牌或网络同步任务。为避免大规模触发堵塞窗口，每批仍让出一帧。对自行使用 Task.Delay 或自建等待队列的第三方动画不保证完全即时；联机同步未做真人实测。

## 构建与测试

维护环境沿用交接文档中的 .NET 9 SDK 和本机游戏／RitsuLib 引用。

```powershell
# 日常开发：只运行本轮专项及相关检查，依赖环境由专项配置自动选择。
./tests020/Run-EngineTests.ps1
# 只查看将执行的范围，不构建、不启动游戏。
./tests020/Run-EngineTests.ps1 -List
# 同一专项需要在完整模组环境检查时：Mode 只改变依赖环境。
./tests020/Run-EngineTests.ps1 -Mode full
# 发布前才显式执行完整回归，分别覆盖完整和最小依赖环境。
./tests020/Run-EngineTests.ps1 -Suite regression -Mode full
./tests020/Run-EngineTests.ps1 -Suite regression -Mode minimal
# 核对完整回归结果，再同步发行目录与 ZIP；本命令不会自动运行游戏。
./Build-Release.ps1
# 只检查发布条件，不生成或覆盖发行文件。
./Build-Release.ps1 -ValidateOnly
```

`tests020/test-profiles.json` 的 `CurrentProfile` 指定本轮专项，`Primary` 列出本次检查，`Related` 列出必要的相关检查。目前为 `release-blockers`，仅执行 `startup`、`release-compatibility`、`skip-animations`，检查新旧版本选择、实际差分加载、原版无色牌筛选及跳过动画的等待、输入和结算。默认 `-Mode auto` 根据专项的 `DefaultMode` 选择依赖环境：当前自动 full；可显式指定 `-Mode full` 验证完整模组环境，环境选择不会启用完整回归。新一轮修改时更新配置；也可以用 `-Profile <名称>` 选择已登记专项，未知名称直接报错，不回退到全部测试。

`Suite` 控制测试范围，`Mode` 控制依赖环境，两者独立。完整回归由 `-Suite regression` 明确启用，保留旧检查及展示。每轮日志、截图、请求和结果放在 `verification/<版本>/runs/<运行标识>/`；结果含范围、专项、依赖环境、执行清单、DLL／探针哈希及测试代码指纹。专项结果与 `regression-full/minimal-result.json` 分开存放，历史 `full/minimal-result.json` 保留。

发布脚本只接受两个环境中明确标为 `regression` 且与当前 DLL、探针和测试源码一致的成功结果；专项通过、旧格式结果或缺少执行清单均不能放行。原来的 `-SkipEngineVerification` 跳过参数已移除。测试入口本身的快速检查可用 `python -m unittest discover -s tests020/python_tests -v`，须使用本机默认 Python。

构建固定引用 `build-deps/ritsulib-0.6.7/` 中的 0.6.7 接口，避免工坊自动更新意外提高最低程序集依赖；SDK 文件不进入发行 ZIP。当前验证副本会刷新已安装工坊依赖，本轮运行时为 RitsuLib 0.6.9。

引擎验证使用游戏副本、独立的 `SlayTheSpire2-Aikun020Test` 用户目录、`--force-steam=off` 及本地测试存储后端。完整模式复制当前已启用工坊模组；测试副本额外固定加载顺序，并固定其模组确认状态，避免首次启动弹窗干扰。原游戏程序集、工坊原件和个人存档不改写。临时探针和测试游戏文件只放在 `verification/0.2.0/sandbox`，不属于发行内容。0.3.0 结果与页面／卡牌截图在 `verification/0.3.0/`，历史结果保留在 `verification/0.2.0/`；发行记录包含 DLL 与 ZIP 的 SHA-256。正式游戏安装不由构建或验证脚本自动更新。
